# 原理讲稿（B站视频用）

> 所有事实来自 `client.js` 与 `docs/DEBUGGING-DESKTOP-INPUT.md`。标 **（未实测）** 的地方不要在图里当结论讲。
> 讲的时候一条主线：**「按住—扫视—松手提交」这个交互，在系统里是免费的，在应用里是要抢的。**

---

## 一、一句话版本

> 它不是系统热键工具，是**跑在 DSH 客户端里的一个插件**：把「我要按什么键」登记给 DSH 自己的快捷键服务，DSH 负责派发和存盘；插件只负责「这个动作用户按下时，我干什么」。唯一需要它亲自抢键盘的时刻，是轮切板按住 `Alt` 的那几百毫秒。

## 二、它到底挂在哪一层

```
┌─────────────────────────────────────────────┐
│ Windows：键盘 → 窗口菜单 / 系统 Alt+Tab       │  ← 我们碰不到，也不去碰
├─────────────────────────────────────────────┤
│ Electron 主进程（DSH 外壳）                   │
│   · setIgnoreMenuShortcuts(true/false)        │  ← 唯一能把 Alt 留在页面里的开关
│   · 原生快捷键桥：只转发 keydown，不转发松开   │
├─────────────────────────────────────────────┤
│ 渲染进程（DSH 内容页）＝ 插件生活的地方        │
│   · ctx.shortcuts.register(...)  登记动作      │
│   · window.addEventListener('keydown/keyup')  │  ← 捕获阶段，自己读手势
│   · React 组件挂进 shell.overlay 画板子        │
└─────────────────────────────────────────────┘
```

关键点：**插件不在最外层，它在最内层**。所以它没有权限、没有驱动、不装服务，也不在你的桌面到处铺东西。

## 三、和 Windows `Alt+Tab` 的六个真实差别

| 维度 | Windows Alt+Tab | 本插件 |
| --- | --- | --- |
| 谁处理按键 | 系统输入层（窗口管理器），全局、跨进程 | 页面 DOM 事件 + DSH 派发，**只在 DSH 窗口有焦点时** |
| 注册方式 | OS 内建 | `ctx.shortcuts.register({ id, regions, modals, resolve })`，键位由用户录、DSH 存 |
| 看见「松开」 | 免费，系统自己就是状态机 | **要抢**：靠 `shortcuts.recording(true)` 让主进程关掉窗口菜单；抢不到就收不到 |
| 快按一次 | 干净地跳一下 | 可能整个手势在 IPC 往返里就结束了 → 有 `tapAlreadyReleased()` 判定，直接跳到第二张，不画板 |
| 画面 | DWM 真缩略图（真实像素） | React 画的文本卡（标题 + 工作区），5 列 × 3 行，超出滚动 |
| 失败方式 | 几乎不会失败 | 会失败，所以有 2 秒接管上限、400 毫秒兜底、失焦即关，且内嵌网页里**拒绝开板** |

**这张表就是视频的骨架**，也是「大老」最想听的部分。

## 四、三个必须讲的故事（有代码支撑）

### 故事 1：Windows 会把你单独按下的 `Alt` 抢走

- 现象：`Alt+Q` 能开板，但板子卡住不切。
- 真相（`docs/DEBUGGING-DESKTOP-INPUT.md`）：Windows 把**裸按 Alt** 交给窗口菜单，之后页面连 `Q` 和 `Alt` 的松开都收不到。控制台里只剩一条 `RAW down AltLeft`。
- 解法：**预接管（preArm）**——页面一看到裸 `Alt`（不带 Ctrl/Meta），立刻调 `ctx.shortcuts.recording(true)`，让主进程执行 `setIgnoreMenuShortcuts(true)`，把整段手势抢回来；同时挂 2 秒兜底，超时自动归还。
- 代价（讲清楚才显得诚实）：接管期间**所有原生快捷键派发被静音**。所以它只在按住 `Alt` 的那一小段时间接管，一松手立刻还。带 `Ctrl` 的组合不接管，`Ctrl+Alt+D` 不会误伤。

### 故事 2：「按下」有人管，「松开」没人管

- 原生快捷键桥只转发 keydown，永远不转发 release。
- 所以板子的状态机是：keydown 开板/前进 → 自己监听 `keyup` 提交。
- 两条退路：`.recording()` 还没真生效时（异步），基础键自己的 keyup 也能提交；浏览器里 `Alt` 松开可能永远不来，则基础键松开后 **400 毫秒兜底**提交。
- 这个「松开才提交 vs 按回车确认」是本项目最核心的取舍。**如果只能讲一个技术点，讲这个。**

### 故事 3：浏览器里那条键根本存不进去

- DSH 的 Web 运行时有一条硬规则：只放行含 `Ctrl` 的双修饰组合，**纯 `Alt` 一律拒绝**（`bindingIssue → unsupported-browser`）。
- 于是浏览器里 `Alt+Q` 存不进去，按什么都不会发生；`Ctrl+Alt+Q` 勉强能用，手感是错的。
- 解法：录制时**只写 DSH 肯存的 `Ctrl+Alt` 那行**，插件从这一行**读出字母**（`webBoardCode()`），再在页面里按**纯 Alt 手势**自己识别。取不到字母就退回 `Q`。
- 附带坑：浏览器里不能搞 preArm（没有 `recording` 通道、也没有窗口菜单），否则手势走两遍，一次点按步进两格 —— 这就是 0.4.12 修的那个 bug。

## 五、板子本身的几个细节（显得真做过）

- **当前会话是第一张，但也在环里**（`board.index` 初始为 1，`moveBoard` 取模），所以绕一圈会回到原会话，和 `Alt+Tab` 一致。
- **网格上限 5 列 × 3 行**（`boardMaxColumns/boardMaxRows`，卡片 190×92），超出的纵向滚动，高亮用 `scrollIntoView({block:'nearest'})` 跟过去，**纯键盘不需要碰鼠标**。
- **它不是对话框**：故意不用 `aria-modal`，因为 DSH 会把 aria-modal 当模态，反而会 block 掉插件自己的命令。
- **候选范围收窄**：只取侧栏里普通可见会话，排除归档、子 Agent、未开始的空白草稿（`visibleSessionIds()`）。
- **能力探测而非版本号**：`officialReady / desktopReady / nextDeveloperReady / webReady` 全靠特征探测（`protocolVersion`、`dshDesktopActions.invoke` 是否存在、`location.protocol === 'dsh-app:'`）。**未知的 Desktop 模式故意不降级成 Web 行为**——宁可不动，不要乱动。
- **每动作可返回 blocked**：`resolve()` 返回 `blocked` 时 DSH 不执行，所以「焦点在内嵌网页」时不是静默失败，而是给一句提示。
- **测试**：42 项 vm 单测，其中「按住 `Alt` 松 `Q` 不提交、600 毫秒仍在板上、再点一下前进、松开 `Alt` 才提交」是新增的守门用例。

## 六、大老可能锤你的 8 个问题（先背下来）

1. **「不就是监听 keydown 吗？」**
   → 不是。`Alt+Tab` 的关键是「松开才提交」，而原生快捷键桥不转发 release；还要先从 Windows 窗口菜单手里把 `Alt` 抢回来。难点在时序和所有权，不在监听。

2. **「为什么不做成系统热键？」**
   → 明确设计成**不接管系统键**。抢占全局热键会和其他软件打架，而且 Ctrl+数字、Alt+Tab 属于用户的肌肉记忆，不该被一个应用私有化。

3. **「`setIgnoreMenuShortcuts` 不是 DSH 录制快捷键才用的吗？」**
   → 是。所以它有个代价：接管期间原生快捷键派发被静音。这条我写进了 README 的「已知边界」，因为功能做通了不等于没代价。

4. **「Electron 的 `before-input-event` 里 `preventDefault()` 不就截住了？」**
   → 实测结论：`preventDefault()` 只改默认行为，**页面仍可能收到 DOM 事件**，不能假设「拦了就等于收不到」。这条写在调试手册里。

5. **「为什么浏览器里是 Ctrl+Alt+数字？」**
   → 因为 `Ctrl+1~9` 是浏览器切标签页的，页面根本收不到。插件不去对抗浏览器，改成错开一个修饰键。

6. **「你怎么保证不误伤别的 Alt 快捷键？」**
   → 三个收窄：只在裸 `Alt` 按下时接管；带 `Ctrl`/`Meta` 的组合不接管；接管期间按到无关按键立刻归还；另有 2 秒上限。

7. **「macOS / Linux 呢？」**
   → 老实说暂无真机验证，只在代码里按桥接能力降级。**不要吹跨平台。**

8. **「这些你都自己写的？」**
   → 见下面第七节，这句话有标准答法。

## 七、关于「几乎没写代码」这件事（重要）

视频里和面试里都**不要**说「这是我一个人写的」。一旦对方追问实现细节，你会当场崩掉，而且这属于夸大。

**建议的实话版本：**

> 这个插件是我用 AI 编码助手结对做出来的，我负责需求、交互规格、验收和发布分发；代码我逐段读过，能讲清每个设计取舍，也能自己改。

这个叙事在今天反而稀缺：它同时证明**产品判断 + AI 协作工程 + 发布运营**。但要让它站得住，你需要两样东西：

1. **能讲清原理**（这份文档就是干这个的）；
2. **有自己动手的痕迹**——哪怕只是亲手加一个动作、改一个默认字母、写一条测试。有了 commit，「我几乎没写代码」就变成「我主导开发并维护」。

另外把增长数据留档：Star 曲线截图、下载/安装量、每期视频的播放和转化。面试讲「我把一个产品推出去」要有数字，不是形容词。
